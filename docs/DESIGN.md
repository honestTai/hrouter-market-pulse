# HRouter 股票工作台 重新设计方案 v0.3（功能报告）

> 2026-10-17 · 方向已确认；第 1 期在 1.7.0、其余（除接真实券商）在 1.8.0 实现，状态见第 11 节
> 依据：本仓库 1.6.2 的代码、本机数据目录里 6 个账户和最近两天的运行记录、GitHub 上的交易类 skill 仓库（第 5 节）；结构参考 `Desktop/video/workbench/docs/DESIGN.md`。

## v0.3 已定下的事

| 事项 | 决定 |
|---|---|
| 运行位置 | 只在本机跑，不做云端 |
| 主控 | **交易员 Agent 就是主控**：它自己写交易策略（代码）并决定执行频率，策略按这个频率自动执行、不花 token；Agent 每隔一段时间（默认 10 分钟，它自己也能改）复查一次，决定保持还是修改（3.4） |
| 默认边界 | **只保留现金 20%**，其他（持股只数、单只上限、总仓位等）默认不限制；所有边界随时可改 |
| 怎么改 | 边界、费率、频率都能在界面里改，也都开放成 MCP 工具（ACP 接入的 Agent 一样能用），每次修改记录是谁改的；你可以把某一项锁住，锁住后 Agent 改不了（4.3） |
| 费率 | 按市场配置，随时可改，界面和 MCP 都能改 |
| 样式 | **全部换成视频工作台那套**（TypeScript + Vite + Tailwind / shadcn，同一套颜色和组件） |

## v0.2 改了什么

| v0.1 | v0.2 |
|---|---|
| 第 3 期上云 | **不做云端，只在本机跑**。桌面壳也只是把本机服务包起来 |
| 「多 Agent」主要讲一个交易员内部的分工 | **多个交易员同时跑**是主场景：每个交易员一个 Agent + 模型，同场模拟；加并发和额度管理（3.2） |

| Skill 库只有自己的 10 个 | **内置 GitHub 上的优秀交易员 skill**，按流派组成交易员模板（第 5 节） |

## 0. 一句话

**一个在你电脑上管多个 Agent 交易员的工作台**：每个交易员是一个 Agent + 模型 + 流派 skill + 前置提示词 + 硬性限制，在真实行情和真实交易规则下同场模拟；你看它们每一轮在干什么、花了多少、谁更好，在关键操作上拍板。现在只接模拟，以后换成真实券商接口时，上面这些都不用改。

## 1. 现状

### 1.1 要保留的

撮合与交易规则（T+1、涨跌停、每手、价位、费用、滑点、成交量上限、停牌、派息拆股）、双源行情核验和 `signalEligible` 闸门、常驻服务（撮合器 + 调度器）、量化策略运行时、48 个 MCP 工具、报告和收盘日报。这些是底座，基本不动。

### 1.2 运行记录里看到的问题（2026-10-15 ~ 16）

| 现象 | 证据 | 根因 |
|---|---|---|
| **仓位上限谁定的说不清** | 6 个账户的风控全是空的（`maxPositionPct` / `maxExposurePct` / `maxDrawdownPct` 都是 null）。Kimi A 股写着「同时持仓不超过 7 只」、Kimi 美股「不超过 8 只」、动量量化「前 3 只」、日内量化「最多 4 只」，Codex A 股自己定成「试仓」，总仓位只有 12% | 上限全是 Agent 开户时**自己写进策略说明**的，你没设过，也改不了；系统里根本没有「最多持有几只」这个设置 |
| 额度用尽还一直调 | Kimi 18:15–19:45 连续 7 轮 `403 5-hour usage limit` | 不识别额度错误；两个 Kimi 账户共用一个登录、一份额度，调度器不知道 |
| 配置能配错 | Claude 运行方式上填了 Kimi 的模型名 `k3-256k`，9 轮失败 4 轮 | 运行方式和模型都是手填，不校验、不试跑 |
| 看不到过程和花费 | 只存输出最后 6000 字；Codex 单轮输出里写着 55k–81k tokens，但没有结构化记录 | 调度跑的是纯文本输出 |
| 很多轮白跑 | 大量「T+1 锁定 / 无变化 → 不交易」的报告 | 固定每 15 分钟叫醒 |
| 新闻对不上 | Codex 报告：「BYRN 新闻接口返回无关内容」 | 新闻搜索没有相关性过滤 |
| 页面按数据类型分 | 7 个页面，「我的持仓」和「竞技场账户详情」大量重复，设置散在三处 | 功能是一期期加的 |

## 2. 数据真实性原则

**模拟盘和实盘唯一的区别是最后一步：订单交给模拟撮合，而不是交给券商。** 从行情到下单前的每一步，都按实盘的标准来做。

### 2.1 原则

1. **只用真实数据**：行情、K 线、新闻、公告、财务、板块、资金流都来自真实的公开源。拿不到就标「拿不到」，交易闸门关闭，不用模拟值或旧值补。
2. **规则按真实交易所**：T+1、涨跌停、最小价位、每手股数、停牌、交易时段、派息拆股都按交易所规则来。
3. **费用按你的券商**：佣金、最低收费、印花税、过户费、规费按你实际开户的券商来配，以后切实盘时两边算出来的钱能对上。
4. **成交判断要保守**：宁可少成交，也不按比实盘更好的价格成交。
5. **每个决定都能追到数据**：每一笔订单记下当时用的报价（来源、时间、两个源是否一致）、新闻和公告链接、K 线截止到哪天。
6. **合成数据不进产品**：合成数据只留在测试里，工作台没有演示模式，也不会和真实记录混在一起。

### 2.2 现在离「真实」还差什么

| 项目 | 现在 | 改成 |
|---|---|---|
| 成交价 | 最新价 ± 5 bp 滑点 | 买单按**卖一价**、卖单按**买一价**（腾讯行情本身就有五档买卖盘），再加滑点；单笔超过一档挂单量时按档位往下吃 |
| 限价单 | 只有在某次同步时价格刚好穿过才成交，两次同步之间的触价会漏掉 | 用真实的 1 分钟 K 线检查同步间隔内的最高价和最低价是否触到限价；只触到不穿过的不算成交 |
| 止损止盈 | 同步时的最新价越过止损止盈价才触发 | 同上，按 1 分钟最高价 / 最低价判断，成交价按实际穿越后的价格，不按止损价 |
| 费用 | 统一的零售费率 | 设置里按券商配置（佣金率、最低收费、是否免五），按市场分开配 |
| 新闻 | 关键词搜索，可能返回无关内容 | 加代码和公司名相关性过滤；拿不到就写拿不到，报告里不能用无关新闻当依据 |
| 数据追溯 | 订单只有理由文字 | 订单附「数据快照」：报价来源和时间、交叉核验状态、引用的新闻和公告 |
| 演示模式 | 面板可以用合成数据启动 | 从工作台移除，只保留截图脚本 |

### 2.3 给以后接实盘留的位置

现在的执行层已经有 broker 抽象（`paper` 模拟盘、`advisory` 建议单）。设计上保证：

```
交易员决策 → 订单意图 → 硬性限制检查 → 纪律检查 → [确认关卡] → broker
                                                          ├─ paper（现在）：模拟撮合
                                                          └─ 真实券商（以后）：只换这一层
```

- 订单意图、限制检查、确认、记录、对账都在 broker 之前做完，**换实盘时只换最后一层**。
- 实盘账户强制「关键操作确认」以上的自主级别，不提供全托管。
- 这一版不写任何真实下单代码，只把接口和记录格式定好。

## 3. 多个交易员同时跑

### 3.1 交易员

交易员 = 一个模拟账户 + 一个 Agent 和模型 + 流派 skill + 前置提示词 + 硬性限制 + 调度 + 自主级别 + 备用 Agent。

**新建交易员（5 步引导）**

| 步骤 | 你要做的 | 工作台帮你做的 |
|---|---|---|
| ① 市场与资金 | 选 A / 港 / 美，初始资金，比赛组别 | 同组默认资金一样，保证可比 |
| ② 流派 | 从交易员模板里选一个（第 5.3 节：游资短线、价值、成长动量、趋势跟随…），或者从空白开始 | 自动带上这个流派的 skill；流派推荐的边界列出来，你勾了才生效 |
| ③ Agent 与模型 | 从 Agent 注册表选一个（Claude Code / Codex / Kimi / WorkBuddy / ACP 接入的其他 / 量化策略），选模型；选一个备用 Agent | 只列出环境检查通过的；模型名按 Agent 校验；**保存前试跑一次只读的小轮次** |
| ④ 前置提示词与限制 | 写这个交易员的前置提示词，设硬性限制（第 4 节） | 模板已经预填；显示最终会发给 Agent 的完整提示词 |
| ⑤ 节奏与自主 | 复查间隔、自主级别 | 说明没变化的时段会自动跳过 |

**自主级别**

| 级别 | 行为 |
|---|---|
| 全托管（现在的模式，模拟盘默认） | 自己选股、下单、写报告，不停下来 |
| 关键操作确认 | 命中规则（新开仓、单笔超过总资产 X%、策略升级）时生成「待你确认」卡片；**过期作废，不会默认执行** |
| 只出建议 | 订单变成建议单，你点了才进撮合 |

### 3.2 同时跑：并发和额度

| 问题 | 做法 |
|---|---|
| 多个交易员同时到点 | 全局并发上限（默认同时最多 4 个 Agent 进程，量化策略不占名额），到点的排队，排队超过 N 分钟就跳过这一轮并记下来 |
| 同一个 CLI 登录被多个交易员共用 | 按「CLI + 登录账号」建**额度池**：两个 Kimi 交易员共用一个池。识别到额度用尽，整个池一起暂停到恢复时间，期间改用各自的备用 Agent，或跳过 |
| 一个交易员内部 | 同一时间只跑一轮（现有规则不变） |
| 配置错误 | 识别「模型不存在、参数冲突、未登录」，直接暂停这个交易员并标红，不再每 15 分钟重复失败 |

### 3.3 每一轮看得见

- **流式运行**：Claude 用 `stream-json`，Codex 用 `exec --json`，Kimi 等走 ACP，解析成统一事件实时推到界面。逻辑和视频工作台的 `runner.ts` / `acp.ts` 一样，抽成共用模块。
- **轮次回放**：看了哪些行情、搜了什么、扫出哪些候选、为什么没买、下了什么单、被哪条限制拦了、报告写了什么。
- **用量和花费**：每轮记录 Agent、模型、tokens、耗时、费用；竞技场加「每百万 token 的超额收益」，比模型时同时看效果和成本。
- **预算**：每个交易员每天的 token 上限，超了自动降频，不影响后台止损。

### 3.4 Agent 当主控：自己写策略、自己定频率

交易员 Agent 不再每一轮亲自看盘下单，而是**写一份代码策略交给系统执行，自己当监督**：

```
Agent（主控，花 token，默认每 10 分钟一次）
  ├─ 写 / 改策略代码（ES 模块，和现在的量化策略同一个运行时）
  ├─ 定执行频率（例如每 2 分钟）、股票池、参数
  ├─ 复查：看策略这段时间的成交、持仓、行情变化 → 保持 / 改参数 / 改代码 / 亲自下单
  └─ 写报告（有变化才写）
策略运行时（不花 token，按 Agent 定的频率）
  └─ 拿真实行情 → 算信号 → 生成订单 → 边界检查 → 撮合
```

- **快**：策略按分钟级执行，不用等模型思考；**省**：token 只花在复查和改策略上。
- **灵活**：复查间隔、执行频率 Agent 都可以通过 MCP 工具自己改（你锁住的除外）；需要判断的时候 Agent 也可以跳过策略直接下单，和现在一样。
- **改策略有护栏**：新版本先用历史数据回测和一次空跑（只算不下单），通过了才上线；每个版本都留着，可以一键回退；成交按版本归因。
- **异常时提前叫醒**：策略报错、连续拒单、持仓大幅波动、持仓股出公告时，不等 10 分钟，立即叫醒 Agent 复查。
- **兼容现在的方式**：不想让 Agent 写代码的交易员，仍可以「每 N 分钟亲自跑一轮」。

### 3.5 团队模式（可选）

默认一个 Agent 跑完整轮。打开团队模式后，一轮按模板拆开，参考 TradingAgents 的分工（第 5 节）：

```
预检(脚本) → 扫描(脚本) → 分析师(Agent，可用便宜模型：技术 / 新闻 / 基本面)
          → 多空辩论(Agent) → 交易员决策(主控) → 硬性限制 + 纪律检查(脚本)
          → 确认关卡(按自主级别) → 下单(脚本) → 报告(主控)
```

主控通过工作台 MCP 工具派活：`dispatch()`、`await_runs()`、`request_confirmation()`、`check_rules()`。能用脚本做的不交给 Agent。

### 3.6 跟交易员说话

- **指令**：「这周不碰半导体」，存成带有效期的指令，之后每轮注入，报告里要回应；到期自动失效。
- **提问**：「为什么昨天买了 300750？」用它的决策日志、成交和报告回答，不触发交易。
- **以后都这样**：你在确认卡片上写这句，主控提议新增一条纪律，你点确认才写入。

## 4. 前置提示词和硬性限制

### 4.1 为什么要分开

**提示词是「告诉 Agent」，限制是「系统拦住」**。现在仓位上限只写在 Agent 自己写的策略说明里，Agent 可以随时改，也可能不遵守；你也没地方设。新设计里：

- **前置提示词**管风格、偏好、语气、关注点，Agent 读了照着做；
- **硬性限制**由撮合前的检查强制执行，违反了订单直接拒绝、记一条拒单，Agent 绕不过去；
- 策略说明还是 Agent 自己写、自己升级版本，但**不能放宽**你设的限制。

### 4.2 前置提示词

三层，从上往下拼，下层可以补充上层：

| 层 | 在哪里设 | 例子 |
|---|---|---|
| 全局 | 设置 → 前置提示词 | 「报告用中文，结论放第一句；引用新闻必须带来源和时间」 |
| 市场 | 设置 → 前置提示词 → A 股 / 港股 / 美股 | 「A 股注意 T+1 和涨跌停；周五尾盘不新开仓」 |
| 交易员 | 交易员 → 设置 | 「只做主板和创业板；偏好有业绩支撑的趋势股；单日最多换一只」 |

每轮发给 Agent 的完整提示词按这个顺序拼：

```
① 系统规则（不可改：只能操作自己的账户、模拟结果不能说成真实收益、数据拿不到就说拿不到）
② 全局前置提示词
③ 市场前置提示词
④ 交易员前置提示词
⑤ 硬性限制摘要（系统按第 4.3 节自动生成，Agent 知道边界在哪）
⑥ 流派 skill（合成后的）
⑦ 有效期内的指令
⑧ 本轮任务
```

交易员页有「预览完整提示词」，看到的就是这一轮实际发出去的内容，并记录在轮次回放里。

### 4.3 硬性限制

每个交易员单独设，留空表示不限制。**默认只开一条：保留现金 20%**，其他都不限制，需要时随时打开。

| 边界 | 说明 | 默认 |
|---|---|---|
| 保留现金 | 现金低于总资产的这个比例时禁止买入 | **20%** |
| 最多持有几只 | 持仓只数到上限后，只能卖或在已有持仓上加仓 | 不限制 |
| 单只最大仓位 | 单只市值占总资产的上限 | 不限制 |
| 每天最多新开几只 | 防止一天换手过多 | 不限制 |
| 每次最多几笔订单 | 防止一次复查里来回折腾 | 不限制 |
| 单笔最大风险 | （买入价 − 止损价）× 股数 ÷ 总资产的上限 | 不限制 |
| 同一行业最大仓位 | 按申万一级行业（A 股）/ GICS（美股）合计 | 不限制 |
| 卖出后冷却 | 卖出后多少个交易日内不能再买回同一只 | 不限制 |
| 禁止范围 | ST、北交所、科创板、价格低于 X、日成交额低于 X | 不限制 |
| 不追涨 | 当日涨幅超过 X% 不买 | 不限制 |
| 回撤熔断 | 从最高点回撤超过 X% 禁止新买入 | 不限制 |

总仓位上限不单独设：保留现金 20% 就等于总仓位最多 80%。

- **哪里检查**：Agent 直接下单时、策略生成订单时、后台撮合挂单前，三处都查。
- **怎么告诉 Agent**：`arena_get_account` 返回剩余空间（「可用现金还能买 23%」「还能再开 2 只」），Agent 不用自己算。
- **拦了怎么显示**：时间线里标红，写明是哪一条；竞技场的「拒单数」按原因分。

### 4.4 随时改：界面、MCP、ACP 都行

边界、费率、频率都不是写死的，有三种改法，效果一样：

| 改法 | 例子 |
|---|---|
| 界面 | 交易员 → 设置，改完立即生效 |
| MCP 工具 | `arena_set_limits`（边界）、`arena_set_fees`（费率）、`arena_set_cadence`（复查间隔、执行频率）、`arena_get_settings`（读当前值和锁定状态） |
| ACP | 通过 ACP 接入的 Agent（Kimi、Gemini CLI、OpenCode 等）挂的是同一套 MCP 工具，一样能改 |

- **谁都能改，但都有记录**：每次修改记下改了什么、旧值新值、是谁（你在界面上、哪个交易员、还是你在 Claude Code 里让 Agent 改的）、理由；显示在交易员时间线里，绩效按修改前后分段。
- **锁**：任何一项都可以点锁。锁住后只能你在界面里改，Agent 调工具会被拒绝并告诉它「这一项被锁定」。默认都不锁。
- **你在别的客户端里也能改**：在 Claude Code / Codex 里说一句「把 Kimi A 股的保留现金改成 30%」，Agent 调这个工具就改好了，不用打开界面。

### 5.2 内置规则

1. **保留许可证和来源**：每个内置 skill 带原仓库的 LICENSE 和 commit 号，写进 `THIRD_PARTY_NOTICES.md`，界面上显示来源链接。
2. **只拿方法，数据换成我们的**：很多 skill 自带脚本，数据来自它们自己的源（akshare、FMP、finviz 等）。内置时把「去哪里拿数据」改成调用我们已核验的工具（`get_quote`、`scan_market`、`get_news`、`query_evidence`…），**默认不跑原仓库的数据脚本**，保证第 2 节的原则。
3. **缺数据就标缺**：skill 需要我们还没有的数据（龙虎榜、涨停池和连板、北向资金、融资融券、市场宽度），在 Skill 库里标「缺数据」，这个 skill 先不能选；把对应的真实数据源补上（第 7 节）之后再开放。不让 Agent 自己编。
4. **标适用市场**：只适合美股的 skill 不会出现在 A 股交易员的选项里。
5. **可升级**：Skill 库里显示上游有新版本，你点了才更新；定制层不受影响。
